# Security review

Final audit before submission (2026-11-19). It covers the API (Express on Render), the frontend (static site on Render), the database (Neon) and the repository. Findings marked **Fixed** were changed in `fix(security): harden API and site headers, throttle logins`.

| Area | What was checked | Result |
| --- | --- | --- |
| Brute force / rate limiting | `/api/login` had no throttling | **Fixed.** 10 failed attempts per client address in 15 minutes, then `429` with `Retry-After`; a successful login clears the count. In memory per instance, which is enough for one Render instance (a shared store such as Redis is needed if the API is scaled out). |
| Authentication | Shared HR password compared with `timingSafeEqual` over SHA-256 digests; signed token (HMAC-SHA256 over the expiry, 12 h TTL); `AUTH_SECRET` generated by Render | OK. Tokens cannot be revoked one at a time; rotating `AUTH_SECRET` logs everyone out. Production would use real identity (OIDC/SSO) and per-user accounts. |
| Demo password | The live password is the one in `backend/.env.example` | **Deliberate.** Reviewers need to sign in, and all data is synthetic. Production would keep the password secret (or use SSO) and never reuse an example value. |
| Authorization / IDOR | Every `/api` route except `/api/health` and `/api/login` requires the token | OK. There is one HR role by design (multi-user roles are out of scope in `REQUIREMENTS.md`), so there is no per-object ownership to bypass. |
| SQL injection | All queries go through Knex with bound parameters; raw fragments are constants; search text has `%` and `_` escaped (tested) | OK |
| XSS | React escapes all output; no `dangerouslySetInnerHTML`, `innerHTML` or `eval` | OK, plus a Content-Security-Policy on the site (below) |
| CSRF | The token is sent in the `Authorization` header, never in a cookie | Not applicable |
| CORS | Explicit allow-list from `CORS_ORIGIN`; other origins get no CORS headers (tested) | OK |
| HTTP headers: API | Was sending `X-Powered-By: Express` and no hardening headers | **Fixed.** `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, `Content-Security-Policy: default-src 'none'; frame-ancestors 'none'`, `Cache-Control: no-store` (salary data is never cached); `X-Powered-By` removed. Render adds HTTPS. |
| HTTP headers: site | Render served HSTS and `nosniff` only | **Fixed** in `render.yaml`: a CSP limited to the site, the API and Google Fonts; `X-Frame-Options: DENY`; `Referrer-Policy`; `Permissions-Policy`. Every page was loaded under this CSP with no violations before release. |
| Input validation | Zod on every body, query and id; strict objects reject unknown fields; amounts are integers within bounds; dates cannot be in the future or before the hire date | OK |
| Error handling | A 200 KB body returned `500`; a duplicate email `409` echoed the database detail | **Fixed.** Oversized bodies return `413`, other body-parser client errors their own 4xx, and `409` returns a plain message. Unexpected errors still return a generic `500` and are logged on the server only. |
| DoS | Page size and feed limit ≤ 100; search ≤ 200 characters; JSON body ≤ 100 KB; aggregate queries are bounded | OK. The free Render plan is the main limit; there is no global request rate limit. |
| Transactions and concurrency | Employee and hire salary are inserted in one transaction; salary history is append-only, so concurrent changes cannot overwrite each other; same-day changes resolve by the order they were recorded (new regression test) | OK. Concurrent edits to employee details are last-write-wins, which is acceptable for a single HR user. |
| Salary calculations | Integer cents; positive `CHECK`; amount capped at 10^12 cents; conversion rounded once; percentiles in a single currency or converted per salary first (tested by hand-computed values) | OK |
| Secrets | Git history scanned for connection strings, Neon keys and passwords; only `.env.example` files are tracked; `.env` and `.neon` are ignored; Render secrets are entered in the dashboard (`sync: false`) | OK |
| Dependencies | `npm audit` on backend (including dev) and frontend | 0 vulnerabilities |
| Docker | `docker-compose.yml` published Postgres on all interfaces with password `postgres` | **Fixed.** Bound to `127.0.0.1`; local development only. |
| CI | Workflows ran with the default token permissions | Change prepared (`permissions: contents: read`). Pushing it needs a GitHub token with the `workflow` scope. |
